## Порядок выбора правил

Диспетчер выбирает правила в таком порядке:

1. `Base Pack`: всегда включить обязательные правила из раздела `Минимальный пакет правил`.
2. `Mission Pack`: определить `mission_type` по `D2_ARCH-SYM-DISP-MISSION_TYPE_REGISTRY` и взять профильные правила.
3. `Client Pack`: определить `client_id` по `D2_ARCH-SYM-DISP-CLIENT_ROUTING_REGISTRY` и добавить клиентские правила/контур.
4. `Source Pack`: определить источник по `D2_ARCH-SYM-DISP-INTAKE_SOURCE_REGISTRY` и добавить правила источника, RAG, физической библиотеки или безопасности.
5. `Agent Pack`: выбрать агентов по `D2_ARCH-SYM-DISP-AGENT_LAYER_REGISTRY` и добавить правила роли/зеркала/приемки.
6. `Tool Pack`: выбрать инструменты по `D2_ARCH-SYM-DISP-TOOL_REGISTRY` и добавить правила статуса подключения.
7. `Risk Pack`: если есть деньги, право, публичное обещание, безопасность, перенос файлов или изменение архитектуры, включить `G`-режим и профильные gates.

## Стоп-условия

Диспетчер не передает миссию в слой 3, если:

- не выбран `mission_type`;
- не собран `Base Pack`;
- нет правила для источника входа;
- нет правила для выбранного инструмента;
- задача с ролью/агентом не проверена через role mirror;
- задача меняет архитектуру, деньги, право, безопасность или публичное обещание без `G`-режима;
- в `Reference Pack` нет ссылок на правила, по которым исполнитель должен работать.

## Минимальный пакет правил

Для любой миссии диспетчер обязан включить в `Reference Pack` минимум:

- главный индекс Симбиота;
- паспорт `sym_dispatcher`;
- карту диспетчерской;
- правило графовой связности;
- правило режима `R/G/БРОСОК`;
- профильные правила миссии из `MISSION_TYPE_REGISTRY`.
