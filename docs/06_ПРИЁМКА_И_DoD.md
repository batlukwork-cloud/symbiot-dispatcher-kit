## Назначение

Методика определяет, когда результат задачи можно принять, а когда он остается черновиком.

## Универсальный DoD

Результат принимается, если:

- Понятно, какую задачу он закрывает.

- Назначены роли исполнения и проверки.

- Создан Obsidian-документ с внутренними ссылками ....

- В физической папке создан человекочитаемый файл Word/Excel/PDF.

- Нет рабочих .md в физической папке роли.

- Обновлен профильный реестр.

- Результат зафиксирован в логе дня.

- Есть следующий шаг или решение о завершении.

## Контроль качества методики

Методика роли принимается, если содержит:

- назначение;

- входные данные;

- алгоритм;

- методы анализа;

- выходные документы;

- критерии приемки;

- связи с ролями и правилами;

- физическое зеркало.

## Методологический контроль качества

Контролер качества не ограничивается проверкой наличия файлов и формы. Он проверяет уровень методологии.

Методика принимается только если указан хотя бы один источник доверия:

- внутренняя база клиент и база знаний владелец продукта;

- российская институциональная практика;

- международная институциональная практика;

- экспертная разработка клиент с алгоритмом и планом проверки.

Целевой уровень - комбинированная методика: внутренняя база клиент + российская институциональная практика + международная рамка + экспертная адаптация клиент.

## Расширенный чек-лист методологической приемки

| Блок | Контрольный вопрос | Приемка |
|---|---|---|
| Основание доверия | Указано, на чем основана методика | обязательно |
| Российский контур | Проверены применимые российские институты, регламенты, базы или банковская практика | если применимо к РФ |
| Международный контур | Проверены международные стандарты, фреймворки или лучшие практики | если есть релевантный стандарт |
| Экспертная логика клиент | Понятно, что является авторской адаптацией и почему ей можно доверять | обязательно для авторских методик |
| Методы анализа | Перечислены конкретные методы: SWOT, PESTEL, benchmark, sensitivity, DD, risk matrix и т.д. | обязательно |
| Входные данные | Понятно, какие документы, базы, таблицы и факты нужны | обязательно |
| Выходной результат | Понятно, какой отчет, таблица, вывод или решение создается | обязательно |
| Проверяемость | Есть критерии приемки результата | обязательно |
| Ограничения | Указано, где методика неприменима или требует осторожности | обязательно |
| Читаемость | Word/Excel/PDF можно открыть и понять человеку без Obsidian | обязательно |
| Связность | Есть связи ... с ролью, реестром, процессом и правилами | обязательно |

## Выход

- статус: принято / принято с замечаниями / не принято;

- список замечаний;

- роль-ответственный за исправление;

- срок или следующий шаг.
