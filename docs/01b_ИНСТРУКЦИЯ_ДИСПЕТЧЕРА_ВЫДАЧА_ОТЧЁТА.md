# Инструкция `sym_dispatcher`: выдача отчёта

## Назначение

Эта инструкция задаёт единый формат выдачи отчёта диспетчера — и для
cron/автоматического прогона `symbiot_inbox_watcher`, и для ручного `--scan` /
`--run` / `--report` конвейера `symbiot_dispatcher.py`.

Цель — чтобы владелец продукта из любого отчёта сразу видел **четыре вещи**:

1. на какую **миссию** и **клиента** ссылается заявка;
2. **план → факт** по каждой заявке;
3. **как проверялся результат**;
4. где физически лежат **документы и ссылки** (полными адресами).

## Жёсткие правила формата

1. **Русский язык.** Без канцелярита и англоязычных сокращений в теле отчёта.
   Исключение — технические идентификаторы (`client_id`, `mission_type`,
   имена gates, пути), они остаются как есть.
2. **Каждый блок ссылается на миссию.** Строка о заявке всегда содержит
   `mission_type` + `client_id`, а не только имя файла.
3. **План → факт.** Для каждой заявки пишется, что планировалось сделать и
   что фактически произошло.
4. **Проверка результата.** Для каждой заявки указывается конкретный способ,
   которым подтверждён факт (адрес, размер, причина gate).
5. **Ссылки и документы — отдельным блоком**, полными адресами, чтобы было
   видно, где именно лежит каждый артефакт.

## Структура отчёта

### Блок 1. Шапка (сводка прогона)

```text
📥 Диспетчер: обработка 01_INBOX — <дата время>
Сканировано заявок: <N>
  └ опознано и направлено: <X>
  └ на опознании (нужен владелец продукта): <Y>
```

### Блок 2. Карточки заявок (план → факт)

По каждой заявке — компактная карточка:

```text
[SIG-XXXXX] <имя заявки>
  Миссия:       <mission_type> · клиент <client_id>
  План:         <что планировалось: куда и как направить>
  Факт:         <что реально сделано: ROUTED / GATE / SKIP / ERROR>
  Как проверено: <адрес / размер / причина — чем подтверждён факт>
```

### Блок 3. Как проверялся результат

Явный подраздел, чтобы верификация не смешивалась с карточками:

```text
Проверка результата:
  [SIG-XXXXX] — папка/файл существует по адресу <путь>, размер <N> байт
  [SIG-YYYYY] — содержимое скопировано, мусорные каталоги отброшены
  [SIG-ZZZZZ] — gate: причина «<причина>», ждёт решения человека
```

### Блок 4. Ссылки и документы

Все адреса — полными путями, отдельно от повествования:

```text
Документы и источники:
  Реестр клиентов:      <рабочая папка>
 Реестр миссий: ...
 Карточка миссии (MCC):<рабочая папка>
 Итоговый отчёт: <рабочая папка>
  Сводка Excel/CSV:     <рабочая папка>
  Целевая папка клиента:<рабочая папка><папка клиента>\...
```

## Значения полей карточки

| Поле | Что писать | Откуда берётся |
|---|---|---|
| Миссия | `mission_type` из реестра миссий (`CLIENT_INVEST_FINANCIER`, `CLIENT_REQUEST_INTAKE`, `TASK_INTAKE_ROUTING`, `SOURCE_INGEST`) + `client_id` | `make_decision()` конвейера |
| План | целевое действие до исполнения: «направить в <путь>», «оставить на gate» | решение диспетчера |
| Факт | фактический статус: `ROUTED` / `GATE` / `SKIP_PERSONAL` / `ERROR` | результат `execute_routing()` |
| Как проверено | признак верификации: существование по адресу, размер, причина gate | `resolved_path`, `size_bytes`, `gate_results` |

## Связь с кодом

Конвейер `symbiot_dispatcher.py` обязан выдавать отчёт ровно по этой структуре:

- `--scan`  → блоки 1–3 (карточки + проверка) в консоль/Telegram;
- `--run`   → блоки 1–3 + результат раскладки;
- `--report`/`--run` → блок 1–4 в файл `DISPATCHER_RUN_LOG.md` (полные адреса
  в блоке 4 обязательны именно в файле).

## Критерии готовности инструкции

Инструкция считается применимой, если любой отчёт диспетчера (cron или ручной)

- отвечает по-русски;
- каждая заявка содержит строку «Миссия» с `mission_type` и `client_id`;
- по каждой заявке видно «План» и «Факт»;
- по каждой заявке видно «Как проверено»;
- все документы вынесены отдельным блоком с полными адресами.
